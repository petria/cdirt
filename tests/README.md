# C-Dirt verification suite

The suite checks the C implementation and its shipped zone data. A source
catalog is inventory only; runtime coverage is tracked separately and must not
be inferred from a successful parse, compile, or catalog check.

## Run locally

Build the one supported image tag, then run structural checks and isolated
server scenarios:

```sh
docker build -t cdirt:latest .
python3 -m unittest discover -s tests -v
python3 tests/docker_smoke.py
python3 tests/docker_light_audit.py
python3 tests/docker_quest_smoke.py
python3 tests/docker_quest_audit.py
python3 tests/docker_zone_walk.py --strict --report /tmp/cdirt-zone-walk.json
python3 tests/coverage_report.py
```

All Docker runners launch a disposable container on a dynamically chosen
loopback port, create throwaway players, and remove the container afterward.
They do not connect to or restart the live instance on port 6715. The quest
runner uses the image's configured unveil password so it can teleport to remote
quest locations; set `CDIRT_TEST_UNVEIL_PASS` if the image was built with a
custom `CDIRT_UNVEIL_PASS`.

`docker_zone_walk.py` does the same for a full world audit. It first reconciles
the source inventory with the `LOC_*` room count generated by C-Dirt's own C
zone loader. The catalog has 2,929 source rooms, while the C build compiles
2,916; the 13 additional rooms are the per-player `wiz.zone` template and are
listed separately. It queries the live C `exits <room>@<zone>` handler for each
compiled room without moving the auditor or triggering traps/combat, and checks
that declared ordinary exits appear. Linked exits are reported separately
because a linked door can be hidden while closed. Start with `--limit 20` when
developing the runner; `--start N` resumes a later batch. The full walk covered
2,916 compiled rooms and 6,990 declared exits and wrote a room-by-room JSON
report; it runs in its own temporary `cdirt:latest` container.

## Inventories and coverage

- `verb_catalog.json` tracks every registered word, aliases, and C dispatch
  route. Its generated `test_cases` are only the scenarios in `scenarios.json`.
  The Docker smoke also invokes each fallback word; this does not cover the C
  handlers assigned to those verbs. The catalog records each word's primary C
  handler, and `coverage_report.py` reports handler and named branch coverage.
- `docker_light_audit.py` covers carried and floor targets for `light` and
  `extinguish`, including a lit room fire, state changes, invalid targets, and
  actor-only output. It protects against silently ignoring carried targets.
- `world_catalog.json` tracks every room header and declared exit, active zone
  files, quest table entries, and C `set_quest()` sites. Four hooks currently
  refer to quest constants absent from the active quest table; they are listed
  separately as legacy/optional hooks and are not active in the successful
  current image build.
- `quest_scenarios.json` links executable end-to-end quest runners to quest and
  zone IDs. `docker_quest_smoke.py` currently exercises Excalibur: retrieve the
  horn from the casket, move to sea, blow the horn, confirm the sword reward,
  and check the quest record.
- `docker_quest_audit.py` replays all 23 non-Excalibur quest routes in fresh
  disposable servers. It uses wizard `goto` and `zap` where needed, so it
  checks C quest/item handlers but does not claim ordinary travel or combat
  coverage.
- `QUEST_AUDIT.md` traces the source-side completion conditions and item/NPC
  prerequisites for all 23 active quests other than Excalibur. It records
  runtime evidence and regression fixes for the previously blocked routes. Only scenarios with
  `status: runtime` count toward automated quest coverage; diagnostic defect
  reproductions and manual notes do not.
- `coverage_report.py` reports remaining gaps. `--strict` exits nonzero until
  every registered word and active quest has a runtime scenario. The zone walk
  covers every inventoried room and its compiled exit list. Use `--verbose` to
  list uncovered words, C handlers, and quests with their C trigger locations.
  A handler having one scenario does not prove all its argument/state branches
  have been tested; those cases and output audiences still need to be authored
  and reviewed explicitly. `--strict-handlers` is a separate gate that remains
  red until every routed C handler has at least one runtime scenario.

Regenerate source inventories after changing verbs, quest definitions, zone
files, or quest specials:

```sh
python3 tests/build_verb_catalog.py
python3 tests/build_world_catalog.py
python3 -m unittest discover -s tests -v
```

## Scenario requirements

Command scenarios can provide `setup`, `values`, `input_role`, and `followups`
to drive reusable multi-player interactions. Each runtime command case should
cover a real input route, relevant valid and
invalid forms, permission and world-state gates, and the state changes the
handler is meant to cause. For output, compare complete C-Dirt text for the
actor, target, same-room witnesses, and excluded remote players. Quest cases
must start from clean world state and assert prerequisites, each trigger,
completion/reward state, repeat behavior, and reset/reload behavior. Keep a
failing sequence as a regression case before changing the game code.

## Exact verb behavior runner

Build the diagnostic profile using the same supported image name:

```sh
docker build -t cdirt:latest \
  --build-arg 'CDIRT_CFLAGS=-O0 -g3 -fno-omit-frame-pointer -fcommon -DCDIRT_DOCKER -DCDIRT_AUDIT --coverage -DCDIRT_COVERAGE' \
  --build-arg 'CDIRT_LDFLAGS=-lm -lcrypt --coverage' .
python3 -m unittest discover -s tests -v
python3 tests/docker_verb_audit.py
python3 tests/handler_branch_report.py
python3 tests/coverage_report.py --verbose
```

`--case <scenario-id>` selects one or more scenarios. The default report is
`/tmp/cdirt-verb-audit/report.json`; its adjacent scenario folders hold the exact
receipts, snapshots, raw socket captures, active preprocessed sources, coverage,
and server log. `--strict` is an eventual completeness gate, and intentionally
fails while complete branch review or registered input evidence is missing.
Declarations and alias names never substitute for executed commands. Prefix
commands record their resolved route without crediting an unexecuted full word.

The audit control is compiled only with `CDIRT_AUDIT` and enabled only when
`CDIRT_AUDIT_SOCKET` is set. It uses a UNIX socket in a private temporary host
folder; no network port or wizard command exposes fixtures. The regular build
has no audit control, captures, or timer override.

A sanitizer profile can add `-fsanitize=address,undefined` to both CFLAGS and
LDFLAGS, with `-fno-sanitize-recover=all` in CFLAGS. Add
`--build-arg CDIRT_ASAN_OPTIONS=detect_leaks=0` to separate generator lifetime
allocations from memory access failures. This option applies to `make gen` only.
Keep `--coverage -DCDIRT_COVERAGE` for this runner. Run diagnostic
profiles sequentially and restore the regular image afterward:

```sh
docker build -t cdirt:latest .
```

See [VERB_AUDIT.md](VERB_AUDIT.md) for findings and review limits. Refresh the
route contracts with `python3 tests/build_verb_contracts.py` after regenerating
the verb catalog; authored scenarios and review notes are preserved.
